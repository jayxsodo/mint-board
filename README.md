# Agent 打新 · 交互看板 (Mint Board)

面向 BSC (Binance Smart Chain) 代币发售、打新进度追踪与 PancakeSwap V2 交易辅助的单文件纯原生看板网页应用。

- **本地文件路径**: `~/agy-bridge/workdir/mint-board/index.html`
- **在线访问链接**: [https://jayxsodo.github.io/mint-board/](https://jayxsodo.github.io/mint-board/)
- **同步清单链接**: [https://jayxsodo.github.io/mint-board/projects.json](https://jayxsodo.github.io/mint-board/projects.json)
- **网络技术规范**: 零外部 CDN 依赖，纯原生 JavaScript 手写 JSON-RPC `eth_call` ABI 编码/解码与 Keccak-256 哈希引擎，杜绝网络封锁与 CDN 故障。
- **资金与安全声明**: **只写代码和发布网页，绝不连接/操作任何钱包去自动交易，不签名、不动钱。代码内绝无任何私钥、助记词字段或收集逻辑。页面内的卖出功能仅供委托方本人连接浏览器 Web3 钱包后亲自核实并签名。默认自带「模拟模式」开关且默认开启。**

## 一、界面与核心功能

### 1. 顶部栏 (Status & Watch Wallet)
- **观察钱包地址**: 默认填入 AW 钱包 `0x1E4Fe11535C8C97eae4226C1820e1C7457b8fB63`，支持手动修改并点击「更新」立即重查。
- **实时指标**:
  - 观察钱包 BNB 余额（实时 `eth_getBalance`）。
  - BSC 实时最新区块高度 + 当前 RPC 节点端到端延迟（毫秒）。
  - BNB 美元现价（基于 Pancake V2 WBNB/USDT 流动池储备毫秒级精确换算）。
  - **清单同步状态**: 实时显示最后同步成功时刻与同步项目数（如 `已同步 23:10:00 (5个)`），网络或解析故障时显示 `同步失败，沿用本地列表`。
- **钱包连接**: 点击「⚡ 连接钱包」唤起浏览器 Web3 钱包（如 MetaMask / Rabby），自动校验并引导切换至 BSC 主网（ChainID 56）。
- **刷新按钮**: 手动触发全量链上读数拉取与同站清单静默同步。

### 2. 打新项目切换与管理
- **项目标签栏**: 预置与同步主流项目，附带状态徽标（`未开盘` / `发售中` / `已开盘` / `已售罄` / `待手动更新`）。
- **快捷键支持**: 键盘直接按 `1` ~ `9` 毫秒级无缝切换不同项目。
- **自定义管理**:
  - 「➕ 添加项目」：弹窗自定义代币合约、发售合约、每份价格、每份代币数、总份数、税率、开售/截止时间、进度函数名及开盘判定函数名等。
  - 「⚙️ 编辑此项目」/「删除项目」。
  - 「📤 导出」/「📥 导入」：全量项目配置可导出为 JSON 文件本地备份或随时还原，自动保留 `source`（sync/manual）来源标记与状态锁定快照。

### 3. 卡 A · 发售进度 (Presale Progress)
- **主视觉指标**:
  - 当前状态与开售时间（附「已开始」/「未开始」标签）。
  - 截止时间动态倒计时（天 / 时 / 分）。
  - 已售份数 / 总份数及彩色发光百分比进度条（采用**高水位锁定**，只增不减）。
  - 距卖满剩余份数。
  - 基准价（每份价格 ÷ 每份代币数，BNB/枚）与每份规则说明。
- **链上实测函数**: 优先调用项目发售合约的视图函数读取链上真实已售进度。若合约不支持或未探通，自动提示并提供手动录入输入框（存入 `localStorage`）。若 RPC 暂时不可达，自动回退展示最近良好快照并注明 `暂时读不到链上，显示上次数据`。

### 4. 卡 B · 价格与收益 (Pancake V2 Price & Returns)
- **流动池储备与现价**: 实时调用 Pancake V2 Factory `getPair` 与 Pair `getReserves` 获取储备，若无储备或未建池明确标识「无池/未开盘」。
- **收益倍数**:
  - **名义倍数**: 当前现价 ÷ 发售基准价。
  - **扣税净倍数**: 扣除该代币专属卖出税（`Sell Tax %`）后的真实到手倍数。
- **单份变现与浮盈**:
  - 1 份代币扣税后实际可换得的 BNB 与美元价值。
  - 池子储备结构（BNB 量 / 代币量）与开盘已持续时长。
  - 实时迷你走势图（Sparkline）与本会话涨跌幅。
  - 我的持有成本与未实现浮盈（BNB 及百分比）。
- **策略提示行 (提示非投资建议)**:
  - 净倍数 ≥ 1.5x：提示「已覆盖成本并具备稳健收益，可考虑卖出」。
  - 净倍数 ≥ 2.0x：提示「净倍数已达 2x+，可考虑先卖回本部分锁定利润」。
  - 净倍数 < 1.0x：提示「破发预警，流动性偏薄，注意风险」。

### 5. 卡 C · 卖出面板 (Sell Panel)
- **代币余额**: 实时读取观察钱包或已连接钱包的 ERC20 `balanceOf`。
- **快捷输入**: 数量输入框配合 `25%`、`50%`、`75%`、`100%` 快捷换算按钮。
- **滑点与路由报价**:
  - 默认滑点 12%（可自定义）。
  - 实时通过 Pancake V2 Router (`0x10ED43...`) 调用 `getAmountsOut` 获得最精准链上预估到手 BNB。
- **模拟模式 (安全机制)**:
  - **默认开启**。开启状态下点击「执行卖出」仅做全流程模拟计算并记录日志，绝不发链上交易。
- **真实卖出流程**:
  - 必须由委托方亲自连接钱包。
  - 弹出二次确认框，严格列明代币、卖出量、滑点、最少到手 BNB。
  - 校验 ERC20 `allowance`，若不足则引导发起 `approve`，随后执行 `swapExactTokensForETHSupportingFeeOnTransferTokens`（兼容带税代币）。
  - 最终签名必须在委托方本人的浏览器插件（MetaMask / Rabby）中人工确认。

### 6. 卡 D · 卖出机器人 (自动化策略监控)
- **策略参数**:
  - 阶梯止盈：支持多行规则（如：达到 2.0x 卖出 50%，达到 3.0x 卖出 25%，达到 5.0x 卖出 25%）。
  - 峰值回撤止盈：达到激活倍数（如 3.0x）后，从最高峰值回撤达设定位（如 15%）触发全卖。
  - 独立滑点与轮询间隔（默认 3000ms，下限 1000ms）。
- **触发机制**:
  - **默认动作**: 仅提醒（写入控制台日志 + 触发浏览器原生 Web Notification 弹窗 + 表格行高亮红色闪烁）。
  - **去卖出面板**: 一键将策略卖出量快捷填入卡 C，由委托方亲自点击并签名。
- **状态安全**: 机器人配置保存在本地 `localStorage`，页面刷新后所有机器人状态自动重置为 `已停止`，杜绝后台误报。
- **心跳监测**: 实时记录每次成功轮询时间，超过 90 秒未收到回包时自动标注红色「⚠️ 疑似卡住」。

### 7. 卡 E · 控制台日志 (Terminal Logs)
- 终端黑底风格实时输出，支持按 `价格监测`、`机器人动作`、`卖出操作`、`系统与同步`、`错误警告` 筛选。
- 价格轮询日志内置节流机制（同项目至少间隔 5 秒一条），避免刷屏。

## 二、projects.json 同步协议

### 1. 清单文件定位与结构
在仓库根目录维护一份静态 `projects.json` 文件，由 Muse 侧在项目开/关流转时维护并推送到 GitHub 仓库。看板页面加载及之后每 60 秒（通过携带 cache-busting 查询参数和 `cache: "no-store"` 的 fetch 请求）自动订阅该清单。

```json
{
  "version": 1,
  "updatedAt": "2026-11-10T23:10:00+08:00",
  "projects": [
    {
      "id": "dogeking",
      "name": "DogeKing 狗王",
      "token": "0xaB36C1C92a3De7462b91306c63C63A4bD5317972",
      "sale": "0xd73A0cDCe58e07D8e2a38EE771Cc3aBC45B6FA45",
      "pricePerShare": 0.002,
      "tokensPerShare": 1000000,
      "totalShares": 10000,
      "taxPct": 0,
      "startAt": "2026-11-10T19:00:00+08:00",
      "endAt": "2026-12-10T19:00:00+08:00",
      "progressFn": "sold",
      "openedFn": "",
      "note": ""
    }
  ]
}
```

### 2. 字段规范
- `version`: 清单协议版本号（当前固定为 `1`）。
- `updatedAt`: ISO 8601 标准带时区时间字符串，记录本次更新时间戳。
- `id`: 项目全局唯一标识，**必须遵循小写英文字母与短横线命名（kebab-case）**。**一旦定下不要修改**，修改 id 在同步协议中等价于「删除旧项目 + 新增新项目」，会丢失用户本地的持有份数与绑定机器人。
- `name`: 项目展示名称（例如 `DogeKing 狗王`、`GOUT`）。
- `token`: ERC20 代币合约地址（42 位十六进制 0x 地址）。
- `sale`: 发售/打新合约地址（42 位十六进制 0x 地址）。
- `pricePerShare`: 单份发售价格（单位：BNB，浮点数）。
- `tokensPerShare`: 单份包含代币数量（整数或浮点数）。
- `totalShares`: 发售总份数（整数）。
- `taxPct`: 卖出滑点/交易税率百分比（例如 `2.0` 表示 2%）。
- `startAt`: 开售时间（ISO 8601 格式，如 `2026-11-10T19:00:00+08:00`）。
- `endAt`: 截止时间（ISO 8601 格式，如 `2026-12-10T19:00:00+08:00`）。
- `progressFn`: 链上已售进度查询函数签名（支持 `sold`、`totalMinted`、`sharesSold` 等）。
- `openedFn`: 链上开盘标记查询函数签名（如 `opened`、`launched`；若合约无该函数可留空 `""`）。
- `note`: 项目备注文案。

### 3. Muse 侧更新工作流
1. 当委托方在 Muse 旁聊流转立项、修改发售参数或完成项目归档结案时，直接编辑本仓库根目录的 `projects.json`。
2. 提交并推送到 GitHub：
   ```bash
   git add projects.json
   git commit -m "chore(sync): update projects manifest"
   git push origin main
   ```
3. 在线看板将在 **60 秒内**自动拉取新清单生效，无需人工刷新页面。

### 4. 增删语义与本地持久化隔离
- **标记隔离**: 清单同步的项目自动标记 `source="sync"`；用户在页面手动添加的项目标记 `source="manual"`，同步引擎永不触碰、永不覆盖、永不删除手动项目。
- **增量更新**: 清单内项目以 `id` 为唯一主键。本地没有则新增（默认持有 0 份）；本地已有则更新合约、价格、份数、税率、时间、函数等，**绝对保留用户本地填写的「我持有份数」、绑定该项目的机器人配置以及状态锁定快照**。
- **结案归档删除**: 上次同步存在、本次清单中消失的 `sync` 项目视为已结案：看板自动将其从项目列表与标签栏移除，妥善重置选中项，并自动停止正在运行的对应机器人，写入控制台审计日志：`[SYS] 项目已结案，已自动移除: <项目名>`。
- **网络容错**: 若由于网络丢包、CDN 节点更新中 404 或 JSON 语法错误导致拉取失败，系统**严格保持当前现状，绝不清空列表**，顶部栏同步状态芯片标注 `同步失败，沿用本地列表`，保障看板高可用。
- **平滑迁移**: 现有用户浏览器 `localStorage` 中已有的预置项目在页面加载时按代币合约地址自动匹配并平滑升级为 `source="sync"`，不丢失任何已填持仓。

## 三、改版 2：状态锁定与最后良好快照机制 (State Latch & Snapshot)

### 1. 根因与设计原则
在上一版本中，状态与进度全靠当次链上 RPC 即时推导。首屏 RPC 偶发超时、网络抖动或函数在某高度返回空时，状态容易回退至「未开盘」，进度也归零。改版 2 实现了**单向单调锁定（Latch）与最后良好快照（Last Good Snapshot）**：

1. **持久化状态结构**: 每个项目在 `localStorage` 中持久化一份独立状态：
   ```json
   {
     "openedLatched": true,
     "openedAt": 1794308400000,
     "soldHighWater": 10000,
     "lastGood": {
       "price": 2.48e-9,
       "sold": 10000,
       "poolWBNB": 11.15,
       "poolToken": 4496000000000,
       "symbol": "GOUT",
       "decimals": 18,
       "ts": 1794324000000
     }
   }
   ```
2. **多源开盘单向置位**: 满足以下任一条件时，立即判定已开盘并永久置位 `openedLatched = true`，记录首次开盘时刻 `openedAt`：
   - 链上 `openedFn` / `launched` 函数返回非零（`true`）。
   - Pancake V2 流动池 WBNB 与代币储备两侧均 `> 0`。
   - 发售进度达到总份数（`soldCount >= totalShares`）。
   此后无论刷新页面多少次、RPC 延迟多高或网络是否掉线，状态**只许停留在已开盘**，绝不回退至未开盘。
3. **高水位进度原则**: `soldHighWater` 单调递增（只增不减）。后续读取失败或偶尔读到更小数值时，一律沿用高水位展示。
4. **首屏即时快照渲染**: 切换或刷新页面时，第一时间使用 `lastGood` 快照与锁定状态进行同步绘制，不等待异步网络往返。新链上数据返回后再静默覆盖更新；若网络断开或 RPC 失败，一直展示快照并标注 `暂时读不到链上，显示上次数据 (数据于 HH:MM:SS)`，杜绝数字清零或跳变。
5. **推导优先级**: `openedLatched > 本次链上证据 > 时间表（未到开售时间才是未开盘）`。「已售罄」同理基于高水位锁定。

## 四、自测试验与验证报告 (Self-Test Verification)

我们在本地纯原生环境以及 Node.js 自动化测试套件中对本次两项改版进行了严格的自测验证，实测结果如下：

### 1. 改版 1 · 项目清单同步自测
- **【实测 1 · 现有配置平滑迁移】**:
  - 操作：模拟老版本 `localStorage` 中存在未带 `source` 标记的 5 个预置项目，且用户在 DogeKing 中输入了 `heldShares = 5`。
  - 结果：加载后 5 个项目自动识别代币地址并赋予 `source: "sync"`，DogeKing 的 `heldShares: 5` 完好无损保留。
- **【实测 2 · 清单增量与用户持仓保留】**:
  - 操作：修改 `projects.json` 中 DogeKing 的 `pricePerShare` 为 `0.0025`，同时本地添加一个 `source: "manual"` 项目，执行同步。
  - 结果：DogeKing 价格参数更新为 0.0025，本地 `heldShares: 5` 依然保持不变；手动项目毫发无损保留。
- **【实测 3 · 结案归档自动移除与机器人联动】**:
  - 操作：启动一个针对 DogeKing 的卖出监控机器人（状态为 `RUNNING`），从 `projects.json` 中移除 `dogeking` 条目并触发同步。
  - 结果：DogeKing 从项目列表与标签栏被安全移除，关联机器人被自动 `stopBot` 并置为 `STOPPED`，控制台日志准确记录 `[SYS] 项目已结案，已自动移除: DogeKing 狗王`。
- **【实测 4 · 异常与断网容错】**:
  - 操作：模拟网络故障抛出异常或 404 响应。
  - 结果：本地项目数组长度未发生任何变更（零项目被清空），顶栏同步芯片由绿色变更为醒目提示 `同步失败，沿用本地列表`，控制台记录 `ERROR` 告警。

### 2. 改版 2 · 开盘锁定与快照回退自测
- **【实测 1 · 状态锁定不回退】**:
  - 操作：对 GOUT 项目置位 `openedLatched = true`，开售时间故意设为未来，刷新页面重新加载。
  - 结果：项目标签栏徽标与卡 A 状态徽标严格显示为 `已开盘`（绿色 `badge-opened`），证明硬编码优先级 `openedLatched > 时间表` 生效。
- **【实测 2 · 模拟断网与 RPC 故障注入】**:
  - 操作：将底层 RPC 调用强制 Mock 抛出网络异常，调用 `refreshActiveProject()`。
  - 结果：GOUT 依然稳定显示 `已开盘`，价格依然显示 `2.48e-9 BNB`，池储备依然显示 `11.15 WBNB / 4496.00B GOUT`，进度条依然保持 `10,000 / 10,000 (100.0%)`，进度状态区显式标注 `暂时读不到链上，显示上次数据`，数字零清零，状态零回退。
- **【实测 3 · 高水位递增保护】**:
  - 操作：合约先返回 10,000 份，随后注入异常数据 0 份。
  - 结果：`soldHighWater` 稳定维持 10,000 份，进度展示与已售份额均未发生倒退。

## 六、网络与容错架构

1. **五节点自动轮换故障转移 (Failover)**:
   - `https://bsc-dataseed.bnbchain.org`

   利用 `document.hidden` 监听标签页状态，当用户切到其他浏览器标签页时自动停止无意义的高频刷新，切回时立刻激活恢复并重新静默同步清单。
